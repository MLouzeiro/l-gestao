Todas as funcionalidades do sistema

Fases 1–16 + sprints E2–E6 entregues com TDD (regras puras testadas antes da implementação).

🔐

M1 — Auth, Empresas, Usuários

  • Better Auth: sessão em DB revogável, cookie httpOnly (sem localStorage)
  • 2FA obrigatório para ADMIN (TOTP + códigos de recuperação)
  • Convite por e-mail com aceite; último ADMIN protegido
  • Multi-empresa: seleção pós-login, papéis por empresa
📦

M2 — Estoque

  • Livro imutável (stock_movements append-only) + cache de saldo
  • Custo médio móvel; FIFO previsto; 11 tipos de movimento
  • Reserva em CONFIRMADO, consumo em FATURADO, liberação em cancelar/expirar
  • Inventário com contagem → diferença → ajuste; cron de expiração de reservas
🧾

M3 — Vendas

  • Estados DRAFT → CONFIRMED → BILLED → CANCELLED/RETURNED
  • Desconto por papel (vendedor/gerente) validado no servidor
  • Leitor USB de código de barras; kits explodem componentes
  • Cupom não-fiscal 80mm com CSS de impressão dedicado
💳

PDV + Caixa

  • Frente de caixa com atalhos F1–F9 e carrinho em tempo real
  • PIX EMV + QR Code (CRC-16/CCITT), troco automático
  • Caixa: abertura, suprimento, sangria, fechamento com contagem e diferença
  • Venda → faturamento → pagamento à vista em uma transação
💰

M4 — Financeiro

  • Contas a receber/pagar geradas no faturamento e na compra
  • Baixa parcial com validação paid_amount ≤ amount
  • OVERDUE automático por cron diário; status recalculado a cada baixa
  • Parcelas de 1–12×; juros/desconto informativos na baixa
📈

M5 — Relatórios e Dashboard

  • Relatórios de Estoque/Vendas/Compras/Financeiro com filtros e paginação
  • Export CSV (BOM + ponto-e-vírgula + CRLF, moeda pt-BR)
  • Dashboard com KPIs, série diária, funil, top vendedores, próximos vencimentos
  • Gráficos em SVG/CSS puro (sem biblioteca externa)
🏢

E3 — Unidades (Matriz/Filial/Posto)

  • Hierarquia de 3 níveis com validação de ciclo
  • Acesso por usuário: posto A não vê posto B; herança para filhas
  • Estoque-alvo por unidade (mínimo/máximo/reposição)
  • Responsável por unidade; default amplo p/ usuários sem marcação
🔁

E4/E6 — Transferências

  • Fluxo simples (saída+entrada imediata) e workflow DRAFT→SENT→RECEIVED
  • Modo de baixa escolhível: ao enviar ou ao receber
  • Cancelamento com estorno na origem (livro imutável)
  • Custo e lote preservados entre a saída e a entrada
⏳

E5 — Lotes, Validade e Rastreio

  • FEFO automático (First Expired, First Out) com bloqueio de vencido
  • Alertas de validade com janelas configuráveis (ex.: 7/30/90 dias)
  • Rastreio completo: lote → movimentações → venda → cliente
  • Etiqueta térmica 50×30mm para impressão
🧩

E2 — Núcleo SaaS (Módulos)

  • 13 módulos contratáveis por empresa (preset por segmento)
  • Assinatura TRIAL/ACTIVE/PAST_DUE/CANCELED/SUSPENDED
  • Versão de contrato aceita por empresa; planos → módulos
  • Menu dinâmico + gate de servidor por módulo
🛡️

Segurança e Auditoria

  • RLS com SET LOCAL app.current_tenant_id em toda transação
  • tenant_id sempre da sessão — nunca do cliente (fail-closed)
  • audit() em toda mutação sensível (tabela append-only)
  • RBAC no servidor (403), validação Zod em toda entrada, sem vazar stack trace
⚙️

Infra e Qualidade

  • Next.js + Drizzle + PostgreSQL (Neon) na Vercel
  • 449 testes: unit (regras puras) + integração (Postgres real com RLS)
  • GitHub Action: typecheck + testes + migrations no push
  • Crons diários (overdue, reservas); backup automático para Google Drive
Sob o capô

Arquitetura multi-tenant

Shared schema + tenant_id + RLS em toda tabela de negócio. Cada Server Action passa por sessão → empresa ativa → permissão → transação com contexto de tenant.

01 · FRAME

Next.js App Router

Server Components por padrão; Server Actions para mutações; Route Handlers só para auth, exports CSV e crons.

02 · AUTH

Better Auth

Sessões em banco revogáveis, 2FA TOTP, convites, organizações = tenants. Cookie httpOnly, nada em localStorage.

03 · DATA

Drizzle + PostgreSQL

40+ tabelas, migrations SQL versionadas, dinheiro em centavos (integer) e quantidades com 3 decimais.

04 · RLS

Isolamento total

Policy tenant_id = current_setting('app.current_tenant_id') com FORCE — fora da transação a query devolve 0 linhas.

05 · RBAC

Permissões

22 permissões × 6 papéis; requirePermission() no início de toda ação sensível.

06 · AUDIT

Trilha de auditoria

Append-only com antes/depois sanitizado (remove senha/token), IP e user-agent em cada evento.

07 · MONEY

Dinheiro e quantidades

Centavos inteiros no servidor; exibição pt-BR. Proibido float em valor financeiro.

08 · OPS

Deploy e crons

Vercel + Neon + GitHub Actions (typecheck, testes, migrations). Crons: OVERDUE e expiração de reservas.
